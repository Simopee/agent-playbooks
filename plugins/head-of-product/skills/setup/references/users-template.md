# Template: what we know and what we assume about users

The real file goes to `docs/product/users-known-vs-assumed.md` in your project (or the path chosen in setup step 1), in the owner's language. The Head of Product proposes the content, the main session writes it (the agent has no write access), the owner approves.

Sources from strongest to weakest: real user tests and feedback; behaviour data (analytics); search demand (search engine tools); simulated personas (they test only comprehension, never demand). The agent cannot interview people or judge whether an interface feels good to use.

## Usability test

A five-person usability test once a quarter, if the project has a user interface. The testers do not know the service. The tasks are the user's basic tasks, worded without the interface's own vocabulary. Record whether each task succeeded, how long it took and where the tester hesitated. The Head of Product writes the tasks and analyses the results; the owner recruits the testers. Five people find the obvious problems, but they cannot tell you what share of users has them.
